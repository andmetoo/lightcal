# Required features

Owner requirements recorded on 2026-10-29. The 2026-10-30 owner decision in [ADR 0002](decisions/0002-direct-calendars-and-updates.md) supersedes the Windows-only provider and manual-install restrictions below: direct Microsoft Graph, private ICS, and signed automatic update installation are approved. The 2026-10-31 owner request in [ADR 0008](decisions/0008-google-calendar-and-platform-design.md) approves read-only Google Calendar OAuth. The Windows app connects that account in the system browser and loads selected calendars. See [setup and current implementation limits](provider-setup.md). The historical Windows feasibility gate remains documented for the optional legacy adapter.

| Feature | Expected behavior and acceptance |
| --- | --- |
| Weekday display | Show weekday headings and today's weekday/date in both calendar modes and the tray tooltip. Include the weekday in the selected-date description. An optional weekday abbreviation in the tray icon is subject to small-icon legibility testing; it is not a promise of arbitrary text beside the icon. |
| Configurable gray weekdays | Let the user choose any subset of Monday-Sunday, including none/all. Default to Saturday and Sunday. Apply a subtle neutral background to those columns in both themes; the dates remain enabled and readable. Keep this separate from the first-weekday setting. |
| Start with Windows | Off by default; opt-in per-user login startup opens hidden in the tray. Persist the setting, report registration failures, and remove only Lightcal's startup entry when disabled. |
| Check for updates | Provide a manual check in Settings/About. Compare the installed version with the latest stable GitHub release, show the result, and offer the verified release page in the browser. Handle offline, timeout, rate-limit, malformed-response, and no-release states. Check does not download, install, or restart the app. Optional scheduled checking remains off unless separately enabled. |
| Optional global shortcut | Unset by default. Allow capture/change/clear of a global key combination to toggle the compact calendar. Report conflicts without stealing another application's shortcut, preserve the previous working binding on registration failure, and release it on Quit. |
| Calendar selection | List only calendars actually exposed by the approved Windows provider, with display name and a local source/account label where available. Persist checked calendar IDs; show events only from checked calendars. First connection selects none until the user chooses. Support no calendars, no selection, access denied, unavailable provider, stale data, and calendar removal. Read-only; no event/account modification. |
| Current-month emphasis | When displayed year/month equals local today, underline the month title with an accent and show a soft `Current month` badge. Remove both when browsing another month/year. Today returns to the current date/month. This is independent of the today outline and selected-day fill; recompute after local midnight/timezone changes. |
| Event dots | For dates containing events from selected calendars, show up to three small dots below the day number, using calendar colors when available. More events retain three dots; an accessible label/tooltip gives the exact count. No selected-calendar events means no dots. Count all-day, recurring, timezone-converted, and multi-day occurrences correctly; use exclusive end boundaries. Preserve clear today/selection states. *Implementation:* up to three 4 px dots, 3 px apart, in calendar colors (white at 85% on the coral Today tile); days of the adjacent months show no dots. |
| Date size | Owner-approved on November 2, 2026. Settings › Calendar offers **Standard**, **Large** and **Larger** day numbers (14, 16 and 18 logical px). Standard and Large keep the 352 × 432 popup; Larger uses 30 px day tiles in 34 px week rows and a 352 × 444 popup, with the agenda unchanged. Only the day numbers grow. Windows display scaling applies on top. Decision: [ADR 0012](decisions/0012-date-size.md); design: the Date size page of the [design canvas](../design/README.md). |
| Koi pond | Owner request of November 3, 2026. Settings › Calendar offers a **Koi pond** switch, off by default. When on, three vector koi swim slowly behind the day grid at 50 % opacity, under the dates, Today, selection and event dots. The koi move only while the popup can be seen: they hold still, with no timer running, while the display is off, the session is locked, or the popup is completely covered or on another virtual desktop, or when Windows Animation effects is off. Translucent overlays do not count as covering. Window, session, display and setting changes wake them, and nothing runs while the popup is hidden or minimized. Decision: [ADR 0013](decisions/0013-koi-pond.md). |
| Hover follow | Owner request of November 3, 2026. In the calendar grid one rounded highlight follows the pointer from day to day on a critically damped spring (about 330 ms to settle), carrying on from where it is drawn when the pointer moves on, with no queue and no overshoot. The whole cell is the hover and click target. It slides under the selected day and Today, fades out when the pointer leaves the day rows or an arrow key is pressed, and starts fresh at the cell on re-entry. The selected day uses the palette Selected fill so the two stay distinct. With Windows Animation effects off it moves and fades at once; its timer runs only while it moves. Decision: [ADR 0015](decisions/0015-calendar-hover-follow.md). |
| Calendar motion | Owner request of November 3, 2026. Copy crossfades to Copied; an agenda row's details fade in as its corners square; and a month change fades the day rows in without moving them. Settings is unchanged. A selected Today is marked by a short coral underline instead of a ring. Everything applies at once with Windows Animation effects off, the month slide plays only while the popup is on screen, and nothing runs while idle. Decision: [ADR 0016](decisions/0016-calendar-motion.md). |
| Event details | Approved on 2026-11-01 in [ADR 0011](decisions/0011-windows-only-design-refresh.md). Clicking an agenda row expands it in place: time range and duration, location, calendar name and color, **Copy** (details to the clipboard) and **Open**. Open launches the event's page in the provider's web calendar (Google or Outlook) in the default browser, only on user action. Hide Open for private ICS events. Nothing in the app edits events. *Implementation:* rows and all-day chips expand in place and collapse on a second click. Copy writes plain text (title, date and time, location, calendar, link) to the Windows clipboard and shows "Copied" for 1.5 s. Open appears only when the provider supplied a link that passes `updater::is_allowed_event_link`: HTTPS without credentials or a port, `www.google.com/calendar/event` (Google `htmlLink`), or `outlook.office.com`, `outlook.office365.com` and `outlook.live.com` under `/owa/` or `/calendar/` (Graph `webLink`). Links are never fetched. On today the agenda dims past events, marks the current one **Now**, shows "in 3 h 55 min" on the next one; an empty day offers a **Next:** link that selects the next event's day. |
| About links | About includes app version, GPL license, [GitHub repository](https://github.com/andmetoo/lightcal), and [koona.app](https://koona.app). Open links only on user action; no embedded browser, remote fonts, automatic website fetches, or analytics. A heart **Sponsor** button in the settings and About footers, and **♥ Sponsor Lightcal** in the translated tray menu, open [GitHub Sponsors](https://github.com/sponsors/andmetoo); About also lists monthly and [one-time](https://github.com/sponsors/andmetoo?frequency=one-time) sponsorship. Both URLs are exact allowlist entries. |
| Languages | Default to English (`en`) on a fresh installation, even on a non-English OS. Settings offers English, Deutsch (`de`), Español (`es`), Français (`fr`), Português (Brasil) (`pt-BR`), Русский (`ru`), Українська (`uk`), 日本語 (`ja`), 한국어 (`ko`), and 简体中文 (`zh-Hans`) ([ADR 0014](decisions/0014-ten-languages.md)). Persist the selection, update UI/date/accessible text immediately without restarting, and use English if a translation or saved language is unavailable. Do not translate event titles, user calendar names, proper names, URLs, or keyboard combinations. |

## Windows calendar feasibility gate

Use a small disposable Rust probe before choosing package/installer format. Demonstrate calendar enumeration and read-only occurrence queries in the intended distribution model, on supported Windows builds with representative configured accounts. Test missing data, revoked access, and the difference between Windows appointment-store calendars and calendars shown only inside Outlook or another application.

Record package-identity/capability requirements and whether a usable store exists on a clean Windows installation. OS account configuration alone is not evidence that a calendar is exposed to this API. Do not silently replace this provider with direct Google/Microsoft sign-in or ICS subscriptions; bring any blocker to the owner for a scope decision.

Relevant primary sources, reviewed on 2026-10-29:

- [AppointmentManager.RequestStoreAsync](https://learn.microsoft.com/en-us/uwp/api/windows.applicationmodel.appointments.appointmentmanager.requeststoreasync)
- [Windows app capability declarations](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/app-capability-declarations)
- [AppointmentStore Rust bindings](https://microsoft.github.io/windows-docs-rs/doc/windows/ApplicationModel/Appointments/struct.AppointmentStore.html)

These identify an API family to investigate; they do not establish compatibility with this app or distribution model.

## UI and release implications

The October 31 design in [ADR 0008](decisions/0008-google-calendar-and-platform-design.md) replaces the large settings layout with a fixed 448 × 360 panel: Calendar contains theme, date size, week start, shaded weekdays, week numbers, event dots and the koi pond; Accounts contains connections and selected calendars; App contains language, startup, shortcut, tray appearance and manual update checking. About is a separate panel for version, updates, license and links. The Windows Slint UI follows this layout. The same decision removes the Current month chip and underline in favor of a single Today action and a plain date label, superseding the earlier emphasis requirement above.

English, Russian, Spanish and Japanese were first-release requirements; the other six languages were added by [ADR 0014](decisions/0014-ten-languages.md). English is the source catalog; use stable message keys, complete translated sentences and locale-aware pluralization/date formatting instead of concatenated fragments. Japanese, Korean and Simplified Chinese require working system fonts without bundled proprietary fonts or downloaded font assets. Layout, focus, screen-reader text, event counts, update/error messages, and tray/menu labels must be checked in each language. Language changes must preserve selected dates, calendar sources, shortcut, timezone, and weekday preferences.

The design is on the owner's design canvas, mirrored in [design/canvas](../design/canvas/): calendars, settings, provider/shortcut/update states, icons and localized examples. Provider names/events are illustrative, not an assertion that live Windows calendars were accessed. See [the design notes](../design/README.md) for actual completion and validation status.

The complete first release includes these features. The earliest prototype may use synthetic events to validate layout, but cannot claim the calendar integration works or silently drop it from the release.
